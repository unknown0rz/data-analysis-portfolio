# GA4 ECサイトのファネル分析(配送先入力→決済方法入力の離脱)

ダッシュボード:[Looker Studioで見る](https://datastudio.google.com/reporting/2622ee51-e0ef-4960-9e56-24cfc83aec76/page/TlfBG)

![ダッシュボード](images/dashboard.png)

## 概要

BigQueryで公開されているGA4のサンプルデータ(Googleの公式グッズを販売するECサイト)を使用。

1. 分析前に、データの欠け(NULL・抜けている日)と、段階を飛ばして購入した人がいないかを確認
2. 商品閲覧から購入までの6段階で、段階別の到達人数を集計
3. 配送先入力→決済方法入力の到達率を、国別(アメリカ/アメリカ以外)・端末別に比較
4. 集計結果をもとに、Looker Studioでダッシュボードを作成

## 問い

配送先入力まで進んだ購入意欲の高いユーザーのうち、約4割が決済方法入力に進まないのはなぜなのか。

## 仮説

離脱の原因として次の2つを考え、到達率を比べて確かめました。

- **国**:国によって使える決済方法が違うため、アメリカ以外のユーザーは離れやすいのではないか → 国別の到達率を比較
- **端末**:スマホなど画面の小さい端末では入力が面倒なため、離れやすいのではないか → 端末別の到達率を比較

## データと条件

使用データ:`ga4_obfuscated_sample_ecommerce`(BigQuery公開データセット「GA4 Google Merchandise Store サンプル」)

| 項目 | 内容 |
|---|---|
| 期間 | 2020年11月1日〜2021年1月31日(92日間) |
| 使用した列 | `user_pseudo_id`(ユーザー)、`event_name`(イベント)、`device.category`(端末)、`geo.country`(国) |
| 対象イベント | 商品閲覧から購入完了までの6つ。view_item(商品閲覧)→ add_to_cart(カート)→ begin_checkout(購入手続き)→ add_shipping_info(配送先入力)→ add_payment_info(決済方法入力)→ purchase(購入) |
| 人数の数え方 | 期間中に一度でもそのイベントをしたユーザーの数。同じユーザーを重複して数えないため |
| 国の分け方 | 「アメリカ」と「アメリカ以外」の2つ。人数の少ない国は到達率に意味がなくなるため |
| 端末別の人数 | 複数の端末(スマホとPCなど)を使ったユーザーは、それぞれの端末で数えている。そのため、端末別の合計は全体の人数と一致しない |

分析前に確認したこと:

| 確認したこと | 結果 |
|---|---|
| `user_pseudo_id` に空欄(NULL)がないか | 0行 |
| 期間内に抜けている日がないか | 92日すべてにデータあり |
| 段階を飛ばして購入した人が多くないか | 購入者4,419人のうち4,418人が決済方法入力も済ませていた |

[データの入手元(Google)](https://developers.google.com/analytics/bigquery/web-ecommerce-demo-dataset?hl=ja)

## 使用ツール

**BigQuery(SQL)** ([SQLファイル](sql/))
- WITH(クエリを段階ごとに分けて読みやすくするため)
- CASE WHEN(イベント名・端末名を日本語にするため。また、国をそのまま出すと到達者が1人しかいない国の到達率が100%になってしまうため、「アメリカ」と「アメリカ以外」の2つにまとめるため)
- COUNT(DISTINCT CASE WHEN)(同じユーザーを重複して数えないようにするため)
- MAX(CASE WHEN) / SUM(ユーザーごとに「そのイベントをした=1、していない=0」のフラグを付け、合計して人数を出すため)
- SAFE_DIVIDE(分母が0のときに「/」で割ると出てしまうエラーを防ぐため)
- ROUND(整数にすると細かい違いが分からなくなるため、到達率を小数第1位まで出すため)
- MIN / MAX / COUNT(DISTINCT event_date)(データの期間と、抜けている日がないかを確認するため)

**Looker Studio**
- 棒グラフ(段階別の到達人数、国別・端末別の到達率)
- 表(国別・端末別の配送先入力と決済方法入力の到達者数)
- スコアカード(特に見てほしい主要な数字)

## 分かったこと

### 段階別の到達人数

| 段階 | 到達人数 |
|---|---:|
| 1_商品閲覧 | 61,252 |
| 2_カート | 12,545 |
| 3_購入手続き | 9,715 |
| 4_配送先入力 | 9,714 |
| 5_決済方法入力 | 5,751 |
| 6_購入 | 4,419 |

- 商品閲覧から購入までの購入率は7.2%。配送先入力から決済方法入力に進んだのは59.2%で、約4割がここで離脱している。

### 国別の到達率(配送先入力→決済方法入力)

| 国 | 配送先入力 | 決済方法入力 | 到達率 |
|---|---:|---:|---:|
| アメリカ以外 | 5,405 | 3,235 | 59.9% |
| アメリカ | 4,309 | 2,516 | 58.4% |

- 差は1.5ポイントで、ほとんど変わらなかった。

### 端末別の到達率(配送先入力→決済方法入力)

| 端末 | 配送先入力 | 決済方法入力 | 到達率 |
|---|---:|---:|---:|
| タブレット | 219 | 134 | 61.2% |
| モバイル | 3,969 | 2,387 | 60.1% |
| デスクトップ | 5,663 | 3,352 | 59.2% |

- 差は最大2.0ポイントで、ほとんど変わらなかった。
- タブレットは到達者数が219人と他の端末より少なく割合がぶれやすいため、最も高いことに意味があるとは言い切れない。

### 結論

- 「国によって使える決済方法が違う」「端末によって操作しにくい」という仮説は、どちらも支持されなかった。国や端末に関係なく離脱していることから、支払い画面そのものに原因がある可能性がある。

## 工夫した点・苦労した点

- 最初に国別の到達者数と到達率を一緒に出したところ、到達者数1人・到達率100%の国が目に入り、人数の少ない国では割合に意味がなくなると気づいた。アメリカ1国で配送先入力の到達者の約44%を占めていたため、CASE WHENで「アメリカ」と「アメリカ以外」の2つにまとめて比較した。
- ファネルは段階を順番に進むことが前提のため、決済方法入力を飛ばして購入している人が多いと数字に影響してしまう。そこで、MAX(CASE WHEN)でユーザーごとに「そのイベントをした=1、していない=0」のフラグを付け、外側のクエリでSUMで合計して確認した。購入者4,419人のうち4,418人が決済方法入力も済ませており、ほぼ全員が順番どおりに進んでいることを確かめた。
- 最初は人数と到達率を1つの表(棒グラフ付き)にまとめていたが、情報が詰まって見にくく、グラフも小さくて役に立っていなかった。そこで到達率だけを横棒グラフに分け、表には到達者数、グラフには到達率と役割を分けて読み取りやすくした。

## 今後の改善

- 決済画面でエラーが起きていないか、開発担当にエラー数・エラー率を確認したい。
- 配送先入力の後に表示される送料・合計金額が、離脱の原因になっていないかを調べたい。
- ただし本分析にはいくつか限界がある。今回のデータで分かるのは「どこで離れたか」までで、「なぜ離れたか」は推測にとどまる。また、期間(11月〜1月)は年末の買い物シーズンにあたるため、他の時期でも同じ結果になるかは分からない。タブレットは人数が少ないため、期間を長くして人数を増やしたうえで確かめる必要がある。
